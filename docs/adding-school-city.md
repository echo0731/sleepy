# 新增学校与城市推荐数据规范

新增教务入口时必须同时维护 `schools.json` 和 `school_cities.json`。城市推荐按当前目录动态计算，不限制学校数量，也不会根据校名猜城市。仅增加教务网址，或者只在文档中写学校地址，都不会让新学校进入同城推荐。

## 1. 学校入口格式

在 `app/src/main/assets/schools.json` 的顶层数组中增加一个对象。下面是**虚构模板**；学校名、网址、协议及城市都必须换成真实且已经验证的数据，不能把 `example.com` 提交为实际入口。

```json
{
  "sortKey": "S",
  "name": "示例大学",
  "url": "https://example.com/jw/",
  "type": "zf_new",
  "status": "supported",
  "aliases": ["示大", "sldx"],
  "sortKeyFull": "shilidaxue"
}
```

| 字段 | 填写规则 |
|---|---|
| `name` | 目录中唯一的完整显示名称，无首尾空格；括号、空格、连字符、研究生后缀都算名称的一部分。必须与城市表的键逐字一致。 |
| `sortKey` | 校名拼音首字母，大写；普通学校不要使用内部的 `#` 或 `通` 分组标记。 |
| `sortKeyFull` | 校名完整拼音，小写；用于目录及同城学校排序。 |
| `url` | 真实教务登录入口，不是学校介绍主页；填写可实际打开的 HTTP/HTTPS URL，优先 HTTPS。 |
| `type` | 已实现且可路由的 `JwProtocol` 类型。这里的 `zf_new` 仅是例子，不能看到一个网址就猜它的协议。新增协议必须补解析器及相关测试。 |
| `status` | 已验证本科入口用 `supported`，已验证研究生入口用 `grad_supported`。当前目录全量一致性测试要求 URL 非空；待适配状态虽被模型支持，不能照此模板把没有验证的入口标为已支持。 |
| `aliases` | 学校简称、旧名、拼音缩写等搜索别名，字符串数组；只影响搜索，不会自动继承其他学校的城市。 |

新增入口应按现有目录顺序插入；JSON 使用双引号，不允许注释或末尾逗号。不要在 `schools.json` 里额外加 `cities` 字段：当前应用从独立城市表读取城市。

## 2. 城市格式：运行时真正读取的内容

在 `app/src/main/assets/school_cities.json` 现有的 `schools` 对象内增加下面的一项，**保留其他学校和现有来源信息**：

```json
"示例大学": ["广州市", "深圳市"]
```

上面假设学校已经核实在这两个城市有对应教学地点，实际按官网填写。单城市学校也使用数组，例如 `"示例大学": ["广州市"]`。

- 键必须与入口的 `name` 完全相同。不能把“示例大学 - 研究生”简写成“示例大学”；每个目录入口都要单独有一项。
- 城市数组非空，城市名称非空、无首尾空格、无重复。
- 城市必须是 `school_city_boundaries.source.json` 的 `cityNames[]` 中已有的完整名称。通常用地级市，如 `广州市`；直辖市用 `北京市`，自治州保留全名。不要填写省名、区名或未经核实的县级市名。港澳及省直辖区域以实际边界名称为准。
- 县级市通常归到上级地级市，例如共青城市填 `九江市`；不是简单在地名后加“市”。边界表没有对应城市时，先核实行政归属。确属缺失则补合法授权的边界数据、来源和坐标测试，不能改填最近城市凑数。
- 多城市校区写多个城市。只写实际教学地点：不要把招生办、医院、合作单位或尚未启用的规划校区当成学生所在校区。
- 独立学院、分校、独立登录入口以该入口所覆盖的学校或校区为准，不能照抄母校城市。研究生入口只写它实际覆盖的城市，不能未经核实直接复制本科。
- 校名含地名不代表学校在该城市。例如中山大学应核查广州、珠海、深圳的实际校区，不能因为名字含“中山”就填中山市；电子科技大学中山学院是另一个独立入口。
- 学校迁址时更新当前教学城市，停止使用的旧校区应移除；并记录生效时间及依据。仍在使用的新旧校区可以并列。

## 3. 新增或更改城市必须保存核查依据

在同一个文件的 `_campusOverrides` 中，用学校当前正式名称记录官网依据。新条目建议采用以下格式（同样为虚构模板）：

```json
"示例大学": {
  "cities": ["广州市", "深圳市"],
  "sources": ["https://example.com/about/campuses"],
  "reason": "学校官网确认广州校区和深圳校区均开展教学；该教务入口覆盖两校区。",
  "verifiedDate": "YYYY-MM-DD"
}
```

`sources` 至少有一个已阅读、能支持城市结论的官方 HTTPS 链接；`reason` 说明实际教学地点与入口适用范围，迁址还要写时间。`verifiedDate` 换成核查当日日期，仅用于审查记录。单城市的新学校也建议如此记录。已有基准来源字段记录的是历史教育部名单，新增学校的核查不能伪装成已包含在那份名单中，也不要改写原始文件哈希。

如果目录保留旧名或有多个入口，在 `_nameMappings` 中明确关联当前正式名称，例如：

```json
"示例大学 - 研究生": "示例大学"
```

**元数据不会自动修改推荐。** `_campusOverrides`、`_nameMappings`、`_supplements` 都是核查记录；应用实际只读取 `schools`。修改依据后必须同步修改每个对应入口的 `schools` 城市数组。现有测试要求同一 `_campusOverrides` 正式名称及其显式映射入口的城市数组一致；如果本科、研究生或分校覆盖城市不同，应分别记录为独立入口的核查项，不要用 `_nameMappings` 将它们强行合并。

更名时同步修改两份文件的名称，并按需要保留旧名为搜索别名。删除目录入口时同步删除它的城市记录及不再使用的核查记录。不要运行一次性研究脚本覆盖整份 JSON；手动修改或数据生成工具必须保留已核实条目、别名、来源和校区修正。

## 4. 使用行为与权限

进入学校列表不会申请定位或读取位置；用户点击“定位”后才使用 Android 系统权限弹窗，接受精准或大致位置权限。申请 FINE 是为了兼容没有网络定位、只能使用 GPS 的设备，不强制用户选择精准位置。不申请后台定位权限，不保存或向第三方发送坐标。

位置与城市边界、学校城市表均在本地匹配。推荐是同城候选，不是距离排序；误差范围跨越城市时不猜测城市，用户仍可搜索完整列表。获取位置与加载边界并行进行，整体超时 12 秒，离开页面取消；30 秒内、精度合格的系统缓存可立即参与判断，不需要等待 30 秒。进程内仅缓存完整解析后的城市边界索引。

## 5. 边界来源、授权和可复现更新

- 最终数据来源：[阿里云 DataV.GeoAtlas](https://datav.aliyun.com/portal/school/atlas/area_selector)。采集快照来自 [zhChuXiao/ChinaGeoJson](https://github.com/zhChuXiao/ChinaGeoJson)，当前固定提交 `7aa2c5fabc6a892015625898c3482874b233f9de`。
- ChinaGeoJson 的 MIT 是仓库作者的软件许可，不能代替 DataV 地理数据的再分发授权。保留原 MIT 文本与最终来源说明于 `app/src/main/assets/third_party/ChinaGeoJson-LICENSE.txt`；原文件哈希、版本和数据来源保存于 `school_city_boundaries.source.json`，关于页也明确区分两者。
- **尚未确认允许把该 DataV 数据打包进 APK 的明确条款。** [DataV 服务协议](https://www.alibabacloud.com/help/zh/doc-detail/2591895.html)第 5.3 条涉及资料等资源的知识产权和明示同意，并非 GeoAtlas 数据的再分发许可。公开可下载不等于可再分发，发布前需获得明确依据或改用已取得适当授权的数据。

具备数据使用授权后，从固定提交的 `province/` 原文件生成：

```bash
git clone https://github.com/zhChuXiao/ChinaGeoJson.git
git -C ChinaGeoJson checkout 7aa2c5fabc6a892015625898c3482874b233f9de
python scripts/generate-school-city-boundaries.py --source ChinaGeoJson/province --revision 7aa2c5fabc6a892015625898c3482874b233f9de
```

脚本仅使用 Python 标准库；输出 `school_city_boundaries.bin.gz` 和来源清单。保留所有多边形、孔洞及点的顺序，坐标四舍五入到 4 位小数（纬度约 11 米），乘 10000 保存为 32 位整数；gzip 的时间戳固定为 0，相同输入生成相同输出。修改数据源时必须更新提交、来源及授权证据，再运行城市覆盖和坐标回归测试。

`SCB1` 格式按大端序编码：4 字节魔数、int32 区域数；每个区域为 int32 UTF-8 名称字节数、名称、int32 多边形数；每个多边形为 int32 环数；每个环为 int32 点数、重复的 int32 经度和 int32 纬度。第一环是外环，其余是孔洞。Android 打包会解压 `.gz` 并去掉后缀，应用读取 `school_city_boundaries.bin`。加载器流式读取，不构建 JSON 对象树；每个环及每 256 个点检查协程取消，取消后不写入缓存。

## 6. 提交前验证

```powershell
.\gradlew.bat :app:testDebugUnitTest :app:assembleDebug :app:lintDebug
```

macOS/Linux 使用 `./gradlew`。必须看到 `BUILD SUCCESSFUL`，不能跳过或降低失败检查。新增或删除学校时，显式审查并更新 `Schools179CrossValidationTest` 的精确总量基准；涉及 hnust 时同步审查 `SchoolsJsonConsistencyTest` 的精确协议计数。定位测试动态检查完整目录，不能替代这些有意保留的精确基准。

自动检查包括目录与城市表一一对应、唯一名称、非空无重复城市、边界覆盖、全部配置城市参与推荐、核查元数据一致性、多城市校区、真实坐标、孔洞/岛屿、错误数据拒绝、超时与取消。它们不能证明格式正确的城市就是真实教学地点，仍需官网核查。

最后在真实手机确认：进入页面不定位；点击后授权并得到正确城市；拒绝权限仍可搜索；定位权限设置与展开/收起位于卡片底部；设置页不可用时不崩溃；离页停止请求；英文 1 个入口使用单数、多个使用复数。没有为模拟器虚拟定位加入特殊逻辑。
